CalendarTools Privacy Policy / Polityka prywatności CalendarTools

Last updated / Ostatnia aktualizacja: 6 October 2026 / 6 października 2026

Contact / Kontakt: nivixis.tools@gmail.com

English

CalendarTools modifies the appearance and layout of the Google Calendar web interface. It processes the page locally in the user's browser to provide bilingual date labels, resizable panels, day navigation, and access to Google Calendar's native event controls.

Data stored locally

CalendarTools stores only extension preferences in chrome.storage.local, including the enabled state, language order, separator, panel widths, sidebar resizing mode, and diagnostics setting. It may also store the open or closed state of the day panel in the current Google Calendar tab session.

If the user chooses “Selected accounts only”, the email addresses explicitly selected by the user are also stored locally as an account allowlist. The active account address is read from Google's account control to apply this preference; event participants are not used for account identification. The user can remove individual addresses or return to all-account mode from the extension menu. Returning to all-account mode does not erase the saved list.

Calendar and account data

The extension can technically display and adjust interface elements that contain calendar information because it runs on calendar.google.com. CalendarTools does not copy calendar events into its own database, does not store event content, does not request OAuth access, and does not use the Google Calendar API. Event creation or editing is performed by the native Google Calendar interface and remains subject to the user's Google account permissions and Google's privacy terms.

Collection, transmission, and sharing

CalendarTools does not transmit user data, calendar content, email addresses, browsing activity, or extension settings to the developer or to any third party. It has no developer-operated server, analytics, advertising, tracking, or telemetry. It does not sell or share user data.

Remote code

All extension code is included in the installed package. CalendarTools does not download or execute remotely hosted extension code. The embedded day panel loads the signed-in Google Calendar web application from https://calendar.google.com using the user's existing browser session.

Permissions

  • storage: saves extension preferences locally in the browser.
  • Access to https://calendar.google.com/*: enables the extension's user-facing interface improvements only on Google Calendar.

Data retention and deletion

Preferences remain in the browser until the user changes them, resets browser data, or removes the extension. Session-only panel state is limited to the current browser tab session. CalendarTools has no remote copy of this information.

Policy changes

If the extension's data practices change, this policy and the Chrome Web Store disclosures will be updated before the changed version is published.

Polski

CalendarTools zmienia wygląd i układ internetowego interfejsu Google Calendar. Przetwarza stronę lokalnie w przeglądarce użytkownika, aby udostępnić dwujęzyczne etykiety dat, regulowane panele, nawigację po dniach oraz dostęp do natywnych kontrolek wydarzeń Google Calendar.

Dane zapisywane lokalnie

CalendarTools zapisuje w chrome.storage.local wyłącznie ustawienia rozszerzenia, w tym stan włączenia, kolejność języków, separator, szerokości paneli, tryb zmiany lewego panelu oraz ustawienie diagnostyki. W sesji bieżącej karty Google Calendar może być również zapisany stan otwarcia lub zamknięcia panelu dnia.

Jeżeli użytkownik wybierze „Tylko wybrane konta”, adresy e-mail kont wskazanych przez użytkownika są również zapisywane lokalnie jako lista dozwolonych kont. Adres aktywnego konta odczytywany jest z kontrolki konta Google w celu zastosowania tego ustawienia; uczestnicy wydarzeń nie są używani do rozpoznawania konta. Użytkownik może usuwać pojedyncze adresy lub wrócić do działania na wszystkich kontach w menu rozszerzenia. Powrót do wszystkich kont nie usuwa zapisanej listy.

Dane kalendarza i konta

Rozszerzenie może technicznie wyświetlać i dopasowywać elementy interfejsu zawierające informacje kalendarza, ponieważ działa na calendar.google.com. CalendarTools nie kopiuje wydarzeń do własnej bazy, nie zapisuje ich treści, nie prosi o dostęp OAuth i nie korzysta z Google Calendar API. Tworzenie lub edycja wydarzeń odbywa się w natywnym interfejsie Google Calendar i podlega uprawnieniom konta użytkownika oraz zasadom prywatności Google.

Gromadzenie, przesyłanie i udostępnianie

CalendarTools nie przesyła autorowi ani innym podmiotom danych użytkownika, treści kalendarza, adresów e-mail, historii przeglądania ani ustawień rozszerzenia. Rozszerzenie nie ma serwera autora, analityki, reklam, śledzenia ani telemetrii. Nie sprzedaje i nie udostępnia danych użytkownika.

Kod zdalny

Cały kod rozszerzenia znajduje się w zainstalowanym pakiecie. CalendarTools nie pobiera ani nie wykonuje zdalnie hostowanego kodu rozszerzenia. Osadzony panel dnia ładuje zalogowaną aplikację Google Calendar z https://calendar.google.com, używając istniejącej sesji przeglądarki użytkownika.

Uprawnienia

  • storage: lokalny zapis ustawień rozszerzenia w przeglądarce.
  • Dostęp do https://calendar.google.com/*: działanie opisanych usprawnień interfejsu wyłącznie na stronie Google Calendar.

Okres przechowywania i usuwanie danych

Ustawienia pozostają w przeglądarce do czasu ich zmiany, wyczyszczenia danych przeglądarki albo usunięcia rozszerzenia. Stan sesyjny panelu ogranicza się do sesji bieżącej karty. CalendarTools nie posiada zdalnej kopii tych informacji.

Zmiany polityki

Jeżeli sposób przetwarzania danych przez rozszerzenie się zmieni, niniejsza polityka i deklaracje w Chrome Web Store zostaną zaktualizowane przed opublikowaniem zmienionej wersji.
