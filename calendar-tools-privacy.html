CalendarTools Privacy Policy / Polityka prywatności CalendarTools

Last updated / Ostatnia aktualizacja: 11 October 2026 / 11 października 2026

English

CalendarTools modifies the appearance and layout of the Google Calendar web interface. It processes page elements locally in the user's browser to provide bilingual date labels, resizable panels, day navigation, optional linking between Month view and the day panel, and access to Google's native event controls.

Data stored locally

CalendarTools uses chrome.storage.local for extension preferences: enabled state, interface and date languages, separator, panel and menu widths, sidebar resizing mode, extension-interface text size, event card appearance, panel linking and the diagnostics setting. Fresh-install language defaults are selected locally from browser preferences; updates preserve existing choices. The extension does not request the Windows language or fetch translations.

The day panel's open/closed preference is shared across eligible Calendar tabs and windows in the same browser profile and remains available after a browser restart. Newly loaded Calendar pages start on Today; dates in existing windows remain independent. An older per-tab open-state preference may be read once to migrate it to the shared local preference.

Local help/update state records the pending and acknowledged release. After a qualifying Chrome Web Store update, temporary coordination state (a tab identifier, a random internal identifier and an expiry time) prevents duplicate What's new messages across tabs. This is not a Google authentication token and is not sent to the developer. First installations and unpacked copies do not automatically show this update message. Help and release notes are bundled with the extension; date labels are generated locally with the browser's internationalization functions.

If the user chooses Selected accounts only, explicitly selected email addresses are stored locally as an account allowlist. The active account address is read from Google's account control to apply that preference; event participants are not used for account identification. Addresses can be removed in the extension's settings. Returning to all-account mode does not erase the saved list.

Calendar content and Google services

The extension reads and adjusts Calendar page elements, including date labels and elements displaying event information, only to provide its visible interface features. It does not copy events into its own database or store event content in extension storage. It does not request separate OAuth access or use the Google Calendar API.

The embedded panel loads Google's signed-in Calendar web application using the user's existing browser session. Navigation, loading events, creating or editing events communicate with Google through its native application and remain subject to Google account permissions and Google's privacy terms. Local processing by CalendarTools does not mean that Google Calendar itself operates offline.

Transmission and limited use

CalendarTools has no developer-operated server, analytics, advertising, tracking or automatic telemetry. It does not send calendar content, account addresses, browsing history or preferences to the developer or additional data recipients. It does not sell user data. Information handled by CalendarTools is used only to provide its described user-facing features, in accordance with the Chrome Web Store User Data Policy, including its Limited Use requirements. Native Google Calendar communications and voluntary support email are described separately here.

Settings files and diagnostics

Optional export creates a local JSON file containing appearance, language and panel-linking preferences, plus the settings-file format and extension version. It excludes account addresses, events, diagnostics and the shared open/closed preference. Import reads a user-selected file and applies validated preferences only after confirmation; account selection remains unchanged. The extension does not upload these files.

Optional diagnostic messages contain label counts and the type of observed area, not event text or account addresses. They are local console messages and are not automatically transmitted or attached to support reports.

Voluntary support email

Report a problem prepares an editable email draft addressed to nivixis.tools@gmail.com. It adds the extension version and locally available browser or engine name/version. Browser details are kept in page memory, not saved as extension preferences. Accounts, events and logs are not attached automatically. CalendarTools does not send the message; the user decides what to send in their mail application. If sent, the developer receives the sender's email address and chosen message content to respond to and investigate the report. Delivery and storage of that email also depend on the email providers involved.

Code and permissions

All extension code and visual/help assets are bundled in the package. CalendarTools does not download or execute remotely hosted extension code. The Google Calendar application shown in the panel is Google's native website, not remotely downloaded CalendarTools code.

  • storage: local preferences and help/update coordination state.
  • Access to https://calendar.google.com/*: the described interface features on Google Calendar only.

Retention, deletion and changes

Local preferences and help/update state remain until changed or cleared, or the extension is removed. Temporary update coordination expires and is replaced or cleared by the extension. The developer has no remote copy of extension storage. A voluntarily sent support email is separate from extension storage; contact nivixis.tools@gmail.com with requests concerning that correspondence.

If data practices change, the public policy and Chrome Web Store disclosures will be updated before the changed release is published.

Polski

CalendarTools zmienia wygląd i układ internetowego interfejsu Google Calendar. Przetwarza elementy strony lokalnie w przeglądarce, aby udostępnić dwujęzyczne daty, regulowane panele, nawigację po dniach, opcjonalne połączenie widoku miesiąca z panelem dnia i dostęp do natywnych kontrolek wydarzeń Google.

Dane zapisywane lokalnie

W chrome.storage.local zapisywane są preferencje rozszerzenia: włączenie, języki interfejsu i dat, separator, szerokości paneli i menu, tryb zmiany lewego panelu, rozmiar tekstu własnego interfejsu, wygląd kart, połączenie paneli i ustawienie diagnostyki. Domyślne języki nowej instalacji są dobierane lokalnie z preferencji przeglądarki; aktualizacje zachowują wcześniejsze wybory. Rozszerzenie nie prosi o język Windows ani nie pobiera tłumaczeń.

Stan otwarcia/zamknięcia panelu dnia jest wspólny dla objętych działaniem kart i okien tego samego profilu przeglądarki i pozostaje po restarcie. Nowo załadowane strony zaczynają od dzisiaj; daty w istniejących oknach są niezależne. Starszy stan otwarcia zapisany dla pojedynczej karty może zostać jednorazowo odczytany przy migracji do wspólnej preferencji.

Lokalny stan pomocy/nowości zawiera oczekującą i potwierdzoną wersję. Po kwalifikującej się aktualizacji Chrome Web Store tymczasowy stan koordynacji (identyfikator karty, losowy identyfikator wewnętrzny i termin ważności) zapobiega powielaniu komunikatu Co nowego między kartami. Nie jest to token logowania Google i nie jest przesyłany autorowi. Pierwsza instalacja i rozpakowane kopie nie wyświetlają automatycznie tego komunikatu aktualizacji. Pomoc i historia są dołączone do paczki; nazwy dat generowane są lokalnie funkcjami językowymi przeglądarki.

W trybie Tylko wybrane konta adresy e-mail wyraźnie wskazane przez użytkownika są zapisywane lokalnie jako lista dozwolonych kont. Adres aktywnego konta jest odczytywany z kontrolki konta Google wyłącznie w celu zastosowania tej preferencji; uczestnicy wydarzeń nie służą do rozpoznawania konta. Adresy można usuwać w ustawieniach rozszerzenia. Powrót do wszystkich kont nie kasuje zapisanej listy.

Treść kalendarza i usługi Google

Rozszerzenie odczytuje i dopasowuje elementy kalendarza, w tym daty i elementy z informacjami wydarzeń, wyłącznie na potrzeby opisanych funkcji interfejsu. Nie kopiuje wydarzeń do własnej bazy ani nie zapisuje ich treści w pamięci rozszerzenia. Nie prosi o osobny dostęp OAuth i nie używa Google Calendar API.

Osadzony panel ładuje zalogowaną aplikację Google Calendar w istniejącej sesji przeglądarki. Nawigacja, wczytywanie, tworzenie i edycja wydarzeń komunikują się z Google przez jego natywną aplikację i podlegają uprawnieniom konta oraz zasadom prywatności Google. Lokalne przetwarzanie CalendarTools nie oznacza, że sam Google Calendar działa offline.

Przesyłanie i ograniczone wykorzystanie

CalendarTools nie ma serwera autora, analityki, reklam, śledzenia ani automatycznej telemetrii. Nie przesyła autorowi ani dodatkowym odbiorcom treści kalendarza, adresów kont, historii przeglądania lub preferencji. Nie sprzedaje danych. Przetwarzane informacje wykorzystuje wyłącznie do opisanych funkcji dla użytkownika, zgodnie z Chrome Web Store User Data Policy, w tym zasadami Limited Use. Komunikacja natywnego Google Calendar i dobrowolny e-mail do pomocy są opisane osobno.

Pliki ustawień i diagnostyka

Opcjonalny eksport tworzy lokalny JSON z preferencjami wyglądu, języków i połączenia paneli oraz formatem pliku i wersją rozszerzenia. Nie obejmuje adresów kont, wydarzeń, diagnostyki ani wspólnego stanu otwarcia. Import odczytuje plik wybrany przez użytkownika i stosuje zweryfikowane preferencje dopiero po potwierdzeniu; wybór kont pozostaje bez zmian. Rozszerzenie nie wysyła tych plików.

Opcjonalne komunikaty diagnostyczne zawierają liczbę etykiet i typ obserwowanego obszaru, nie treść wydarzeń lub adresy kont. Są lokalnymi komunikatami konsoli; nie są automatycznie wysyłane ani dołączane do zgłoszeń.

Dobrowolny e-mail do pomocy

Zgłoś problem przygotowuje edytowalną wiadomość do nivixis.tools@gmail.com. Dodaje wersję rozszerzenia oraz dostępną nazwę i wersję przeglądarki lub silnika. Dane przeglądarki pozostają w pamięci strony, nie są zapisywane jako preferencje. Konta, wydarzenia i logi nie są dołączane automatycznie. CalendarTools nie wysyła wiadomości; użytkownik decyduje o jej treści i wysłaniu w programie pocztowym. Po wysłaniu autor otrzymuje adres nadawcy i wybraną treść, aby odpowiedzieć i zbadać zgłoszenie. Dostarczenie i przechowywanie e-maila zależy również od użytych usług pocztowych.

Kod i uprawnienia

Cały kod rozszerzenia, grafiki i pomoc są w paczce. CalendarTools nie pobiera ani nie wykonuje zdalnie hostowanego kodu rozszerzenia. Aplikacja Google Calendar w panelu jest natywną stroną Google, nie pobieranym zdalnie kodem CalendarTools.

  • storage: lokalne preferencje i koordynacja informacji pomocy/aktualizacji.
  • Dostęp do https://calendar.google.com/*: opisane usprawnienia wyłącznie na Google Calendar.

Przechowywanie, usuwanie i zmiany

Lokalne preferencje oraz stan pomocy/aktualizacji pozostają do zmiany, wyczyszczenia lub usunięcia rozszerzenia. Tymczasowa koordynacja aktualizacji traci ważność i jest zastępowana lub czyszczona przez rozszerzenie. Autor nie posiada zdalnej kopii pamięci rozszerzenia. Dobrowolnie wysłany e-mail jest odrębny od pamięci rozszerzenia; sprawy dotyczące tej korespondencji można zgłaszać na nivixis.tools@gmail.com.

Jeżeli sposób przetwarzania danych się zmieni, publiczna polityka i deklaracje sklepu zostaną zaktualizowane przed publikacją zmienionej wersji.
