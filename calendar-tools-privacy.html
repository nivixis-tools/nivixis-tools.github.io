CalendarTools Privacy Policy / Polityka prywatności CalendarTools

English

CalendarTools modifies the appearance and layout of the Google Calendar web interface. It processes page elements locally in the user's browser to provide bilingual date labels, resizable panels, day navigation, optional linking between Month view and the day panel, and access to Google's native event controls.

Data stored locally

Version 0.6.21 adds per-weekday working-hour schedules, including optional night shifts and breaks, and up to 12 named schedule profiles. Profiles contain a user-chosen name, starting weekdays and time ranges, not events or account addresses. Other local preferences include the weekday-color master switch, Today/panel-day outline colors and enabled states, the ordered list of pinned menu switches, and automatic/manual menu width. A saved manual width remains available in automatic mode.

Menu language can follow the browser interface language automatically (Polish for PL, English otherwise) or be selected manually. This is resolved locally when preferences are loaded; there is no translation service. New installations start on Automatic; existing explicit PL/EN choices remain manual. Date languages are separate.

The expanded/collapsed state of settings groups is a separate local layout preference. A one-step undo snapshot for the last hours copy or profile application stays only in the current settings page memory until reload or closure. It is unavailable if later edits conflict with restoring the affected hours; it does not change Google Calendar events.

CalendarTools also stores the extension-interface theme, optional month-following and keyboard navigation, weekday colors and their intensity, and working-hours preferences (enabled state, start/end time, selected weekdays, color and intensity). Automatic theme resolves the browser's effective light/dark preference locally; it does not read a custom browser or Google theme palette. Themes affect only CalendarTools' menu, settings, help/history and update notice; separate optional calendar highlights do not change event data.

New installations initialize the day panel as open and the views as linked. Qualifying store updates enable linking once, including where it was previously off; a persistent local migration marker prevents later updates from overriding a subsequent manual choice. Existing closed panels and other preferences are preserved. This marker is not an account identifier and is excluded from settings export.

CalendarTools uses chrome.storage.local for extension preferences: enabled state, interface and date languages, separator, panel and menu widths, sidebar resizing mode, extension-interface text size, event card appearance, panel linking and the diagnostics setting. Fresh-install date-language defaults are selected locally from browser preferences; updates preserve existing choices. The extension does not request the Windows language or fetch translations.

The day panel's open/closed preference is shared across eligible Calendar tabs and windows in the same browser profile and remains available after a browser restart. Newly loaded Calendar pages start on Today; dates in existing windows remain independent. An older per-tab open-state preference may be read once to migrate it to the shared local preference.

Local help/update state records the pending and acknowledged release. From version 0.6.22 the same What's new notice can also appear in the extension toolbar menu. Temporary coordination state (a tab identifier or the extension's own popup-document identifier, a random internal identifier and an expiry time) prevents duplicate notices across Calendar tabs and the toolbar menu. The extension may check whether that specific popup document is still open to recover a notice after the menu closes. It does not inspect other extensions or read the contents of other websites for this check. These internal identifiers are not Google authentication tokens or account identifiers and are not sent to the developer. Only explicit confirmation marks the release as acknowledged; opening release history or closing the menu does not. First installations and unpacked copies do not automatically show this update message. Help and release notes are bundled with the extension; date labels are generated locally with the browser's internationalization functions.

If the user chooses Selected accounts only, explicitly selected email addresses are stored locally as an account allowlist. The active account address is read from Google's account control to apply that preference; event participants are not used for account identification. Addresses can be removed in the extension's settings. Returning to all-account mode does not erase the saved list.

Calendar content and Google services

The extension reads and adjusts Calendar page elements, including date labels and elements displaying event information, only to provide its visible interface features. It does not copy events into its own database or store event content in extension storage. It does not request separate OAuth access or use the Google Calendar API.

The embedded panel loads Google's signed-in Calendar web application using the user's existing browser session. Navigation, loading events, creating or editing events communicate with Google through its native application and remain subject to Google account permissions and Google's privacy terms. Local processing by CalendarTools does not mean that Google Calendar itself operates offline.

Transmission and limited use

CalendarTools has no developer-operated server, analytics, advertising, tracking or automatic telemetry. It does not send calendar content, account addresses, browsing history or preferences to the developer or additional data recipients. It does not sell user data. Information handled by CalendarTools is used only to provide its described user-facing features, in accordance with the Chrome Web Store User Data Policy, including its Limited Use requirements. Native Google Calendar communications and voluntary support email are described separately here.

Settings files and diagnostics

Optional export creates a local JSON file containing appearance, language (including automatic/manual menu-language selection), theme, navigation, weekday-color and outline preferences, weekly working hours and named schedule profiles, pinned-switch order and menu-width mode, plus the settings-file format and extension version. It excludes account addresses, events, group-layout state, the temporary undo snapshot, diagnostics, internal migration/update state and the shared open/closed preference. Import reads a user-selected file and applies validated preferences only after confirmation; account selection remains unchanged. Older files remain supported. Resetting active working hours keeps saved profiles; profiles can be deleted individually in Settings. The extension does not upload these files.

Optional diagnostic messages contain label counts and the type of observed area, not event text or account addresses. They are local console messages and are not automatically transmitted or attached to support reports.

Voluntary support email

Report a problem prepares an editable email draft addressed to nivixis.tools@gmail.com. It adds the extension version and locally available browser or engine name/version. Browser details are kept in page memory, not saved as extension preferences. Accounts, events and logs are not attached automatically. CalendarTools does not send the message; the user decides what to send in their mail application. If sent, the developer receives the sender's email address and chosen message content to respond to and investigate the report. Delivery and storage of that email also depend on the email providers involved.

Code and permissions

All extension code and visual/help assets are bundled in the package. CalendarTools does not download or execute remotely hosted extension code. The Google Calendar application shown in the panel is Google's native website, not remotely downloaded CalendarTools code.

  • storage: local preferences and help/update coordination state.
  • Access to https://calendar.google.com/*: the described interface features on Google Calendar only.

Retention, deletion and changes

Local preferences and help/update state remain until changed or cleared, or the extension is removed. Temporary update coordination expires and is replaced or cleared by the extension. The developer has no remote copy of extension storage. A voluntarily sent support email is separate from extension storage; contact nivixis.tools@gmail.com with requests concerning that correspondence.

If data practices change, the public policy and Chrome Web Store disclosures will be updated before the changed release is published.

Polski

CalendarTools zmienia wygląd i układ internetowego interfejsu Google Calendar. Przetwarza elementy strony lokalnie w przeglądarce, aby udostępnić dwujęzyczne daty, regulowane panele, nawigację po dniach, opcjonalne połączenie widoku miesiąca z panelem dnia i dostęp do natywnych kontrolek wydarzeń Google.

Dane zapisywane lokalnie

Wersja 0.6.21 dodaje harmonogram godzin pracy osobno dla dni tygodnia, w tym opcjonalne zmiany nocne i przerwy, oraz do 12 nazwanych profili harmonogramu. Profil zawiera nazwę nadaną przez użytkownika, dni rozpoczęcia i zakresy godzin, bez wydarzeń lub adresów kont. Inne lokalne preferencje obejmują główny włącznik kolorów dni, kolory i włączniki obwódek dzisiaj/dnia z panelu, kolejność pinezek oraz automatyczną/ręczną szerokość menu. Ręczna szerokość pozostaje zapamiętana przy automacie.

Język menu może automatycznie podążać za językiem interfejsu przeglądarki (polski dla PL, angielski dla pozostałych) albo być wybrany ręcznie. Jest dobierany lokalnie przy odczycie ustawień, bez serwisu tłumaczeń. Nowe instalacje zaczynają od Automatyczny; dotychczasowe jawne wybory PL/EN pozostają ręczne. Języki dat są odrębne.

Stan rozwinięcia/zwinięcia grup jest odrębną lokalną preferencją układu. Jednokrokowa kopia do cofnięcia ostatniego kopiowania godzin lub zastosowania profilu pozostaje tylko w pamięci bieżącej strony ustawień do jej odświeżenia lub zamknięcia. Jest niedostępna przy kolidujących późniejszych edycjach godzin; nie zmienia wydarzeń Google Calendar.

CalendarTools zapisuje również motyw własnego interfejsu, opcjonalne podążanie miesiąca i nawigację klawiaturową, kolory dni tygodnia i ich intensywność oraz preferencje godzin pracy (włączenie, początek/koniec, wybrane dni, kolor i intensywność). Automatyczny motyw odczytuje lokalnie efektywną preferencję jasny/ciemny przeglądarki; nie odczytuje niestandardowej palety motywu przeglądarki lub Google. Motywy obejmują tylko menu CalendarTools, ustawienia, pomoc/historię i okno aktualizacji; osobne opcjonalne tła kalendarza nie zmieniają danych wydarzeń.

Nowe instalacje zaczynają z otwartym panelem i połączonymi widokami. Kwalifikująca się aktualizacja sklepu włącza połączenie jednorazowo, także przy wcześniejszym wyłączeniu; trwały lokalny znacznik migracji chroni późniejszy ręczny wybór przed kolejnymi aktualizacjami. Wcześniej zamknięty panel i pozostałe preferencje pozostają bez zmian. Znacznik nie identyfikuje konta i nie wchodzi do eksportu ustawień.

W chrome.storage.local zapisywane są preferencje rozszerzenia: włączenie, języki interfejsu i dat, separator, szerokości paneli i menu, tryb zmiany lewego panelu, rozmiar tekstu własnego interfejsu, wygląd kart, połączenie paneli i ustawienie diagnostyki. Domyślne języki dat nowej instalacji są dobierane lokalnie z preferencji przeglądarki; aktualizacje zachowują wcześniejsze wybory. Rozszerzenie nie prosi o język Windows ani nie pobiera tłumaczeń.

Stan otwarcia/zamknięcia panelu dnia jest wspólny dla objętych działaniem kart i okien tego samego profilu przeglądarki i pozostaje po restarcie. Nowo załadowane strony zaczynają od dzisiaj; daty w istniejących oknach są niezależne. Starszy stan otwarcia zapisany dla pojedynczej karty może zostać jednorazowo odczytany przy migracji do wspólnej preferencji.

Lokalny stan pomocy/nowości zawiera oczekującą i potwierdzoną wersję. Od wersji 0.6.22 ten sam komunikat Co nowego może pojawić się także w menu ikony rozszerzenia. Tymczasowy stan koordynacji (identyfikator karty lub dokumentu własnego menu rozszerzenia, losowy identyfikator wewnętrzny i termin ważności) zapobiega powielaniu komunikatów między kartami Calendar i menu. Rozszerzenie może sprawdzić, czy ten konkretny dokument menu jest nadal otwarty, aby przywrócić komunikat po zamknięciu menu. Nie sprawdza przy tym innych rozszerzeń ani nie odczytuje treści innych stron. Te wewnętrzne identyfikatory nie są tokenami logowania Google ani identyfikatorami kont i nie są przesyłane autorowi. Dopiero jawne potwierdzenie oznacza wersję jako przeczytaną; otwarcie historii lub zamknięcie menu tego nie robi. Pierwsza instalacja i rozpakowane kopie nie wyświetlają automatycznie tego komunikatu aktualizacji. Pomoc i historia są dołączone do paczki; nazwy dat generowane są lokalnie funkcjami językowymi przeglądarki.

W trybie Tylko wybrane konta adresy e-mail wyraźnie wskazane przez użytkownika są zapisywane lokalnie jako lista dozwolonych kont. Adres aktywnego konta jest odczytywany z kontrolki konta Google wyłącznie w celu zastosowania tej preferencji; uczestnicy wydarzeń nie służą do rozpoznawania konta. Adresy można usuwać w ustawieniach rozszerzenia. Powrót do wszystkich kont nie kasuje zapisanej listy.

Treść kalendarza i usługi Google

Rozszerzenie odczytuje i dopasowuje elementy kalendarza, w tym daty i elementy z informacjami wydarzeń, wyłącznie na potrzeby opisanych funkcji interfejsu. Nie kopiuje wydarzeń do własnej bazy ani nie zapisuje ich treści w pamięci rozszerzenia. Nie prosi o osobny dostęp OAuth i nie używa Google Calendar API.

Osadzony panel ładuje zalogowaną aplikację Google Calendar w istniejącej sesji przeglądarki. Nawigacja, wczytywanie, tworzenie i edycja wydarzeń komunikują się z Google przez jego natywną aplikację i podlegają uprawnieniom konta oraz zasadom prywatności Google. Lokalne przetwarzanie CalendarTools nie oznacza, że sam Google Calendar działa offline.

Przesyłanie i ograniczone wykorzystanie

CalendarTools nie ma serwera autora, analityki, reklam, śledzenia ani automatycznej telemetrii. Nie przesyła autorowi ani dodatkowym odbiorcom treści kalendarza, adresów kont, historii przeglądania lub preferencji. Nie sprzedaje danych. Przetwarzane informacje wykorzystuje wyłącznie do opisanych funkcji dla użytkownika, zgodnie z Chrome Web Store User Data Policy, w tym zasadami Limited Use. Komunikacja natywnego Google Calendar i dobrowolny e-mail do pomocy są opisane osobno.

Pliki ustawień i diagnostyka

Opcjonalny eksport tworzy lokalny JSON z preferencjami wyglądu, języków (w tym automatycznego/ręcznego wyboru języka menu), motywu, nawigacji, kolorów dni i obwódek, tygodniowych godzin pracy i nazwanych profili, kolejności pinezek i trybu szerokości menu oraz formatem pliku i wersją rozszerzenia. Nie obejmuje adresów kont, wydarzeń, układu grup, tymczasowej kopii Cofnij, diagnostyki, wewnętrznego stanu migracji/aktualizacji ani wspólnego stanu otwarcia. Import odczytuje plik wybrany przez użytkownika i stosuje zweryfikowane preferencje dopiero po potwierdzeniu; wybór kont pozostaje bez zmian. Starsze pliki pozostają obsługiwane. Reset bieżących godzin zachowuje profile; można je usuwać pojedynczo w ustawieniach. Rozszerzenie nie wysyła tych plików.

Opcjonalne komunikaty diagnostyczne zawierają liczbę etykiet i typ obserwowanego obszaru, nie treść wydarzeń lub adresy kont. Są lokalnymi komunikatami konsoli; nie są automatycznie wysyłane ani dołączane do zgłoszeń.

Dobrowolny e-mail do pomocy

Zgłoś problem przygotowuje edytowalną wiadomość do nivixis.tools@gmail.com. Dodaje wersję rozszerzenia oraz dostępną nazwę i wersję przeglądarki lub silnika. Dane przeglądarki pozostają w pamięci strony, nie są zapisywane jako preferencje. Konta, wydarzenia i logi nie są dołączane automatycznie. CalendarTools nie wysyła wiadomości; użytkownik decyduje o jej treści i wysłaniu w programie pocztowym. Po wysłaniu autor otrzymuje adres nadawcy i wybraną treść, aby odpowiedzieć i zbadać zgłoszenie. Dostarczenie i przechowywanie e-maila zależy również od użytych usług pocztowych.

Kod i uprawnienia

Cały kod rozszerzenia, grafiki i pomoc są w paczce. CalendarTools nie pobiera ani nie wykonuje zdalnie hostowanego kodu rozszerzenia. Aplikacja Google Calendar w panelu jest natywną stroną Google, nie pobieranym zdalnie kodem CalendarTools.

  • storage: lokalne preferencje i koordynacja informacji pomocy/aktualizacji.
  • Dostęp do https://calendar.google.com/*: opisane usprawnienia wyłącznie na Google Calendar.

Przechowywanie, usuwanie i zmiany

Lokalne preferencje oraz stan pomocy/aktualizacji pozostają do zmiany, wyczyszczenia lub usunięcia rozszerzenia. Tymczasowa koordynacja aktualizacji traci ważność i jest zastępowana lub czyszczona przez rozszerzenie. Autor nie posiada zdalnej kopii pamięci rozszerzenia. Dobrowolnie wysłany e-mail jest odrębny od pamięci rozszerzenia; sprawy dotyczące tej korespondencji można zgłaszać na nivixis.tools@gmail.com.

Jeżeli sposób przetwarzania danych się zmieni, publiczna polityka i deklaracje sklepu zostaną zaktualizowane przed publikacją zmienionej wersji.
